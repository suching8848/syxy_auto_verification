# 终端工具 → 图形界面 exe 改造方案

> 目标：让非技术用户双击一个 exe 就能看懂并用起来，不再面对终端菜单。
> 约束：**继续零第三方依赖**（tkinter 属标准库），保留现有 CLI 与测试。
> 状态：**已实施**（阶段 1–4 完成，见文末"实施结果"）

---

## 0. 两个真实使用场景

方案的全部取舍都来自下面这两个场景。**关键认知：两者要做的事完全一样**——启动后一直探测网络，断网就立刻自动重连——区别只在**启动方式**和**外壳**。

### 场景 A —「手动启动，想看着它干活」

- 启动：用户双击 `CampusNet.exe`，点「开始守护」
- 界面：窗口 + 托盘图标
- 行为：持续探测；断网自动重连；**一直守护到你点「停止守护」或托盘退出**
- 收尾：点 ✕ 缩到托盘继续守护（托盘右键才是真退出）

### 场景 B —「每天固定时刻要重新认证，别让我管」

- 启动：计划任务每天到点自己拉起，`--silent`
- 界面：**完全没有**（无窗口、无托盘、无弹窗）
- 行为：同样的持续探测 + 断网即刻重连
- 收尾：跑满 `silent_run_minutes` 后自己退出，只在 `logs/` 留一份记录

> 场景 B 与场景 A 的本质差异：A 是「人开、能看见」，B 是「到点自己开、什么都看不见」。

## 1. 界面设计

### 1.1 主窗口

一屏搞定，不做菜单栏、不做多标签页。多一个页面就多一分看不懂。

```
┌─ 校园网自动认证 v1.6.1 ───────────────────────────── ─ □ ✕ ┐
│  校园网自动认证 v1.6.1                    断网自动重连 · 守护中 │
│                                                              │
│  ● 守护中                                                    │
│    网络正常 · 上次检测 22:36:14                               │
│    已守护 12m3s　·　重连 2 次 · 最近 22:35:02（耗时 2 秒）     │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │                 ■  停止守护                            │  │  ← 主按钮
│  └────────────────────────────────────────────────────────┘  │
│  [停止守护] [立即认证一次]                                    │
│                                                              │
│  ▾ 运行日志            详细日志          打开日志文件夹        │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 22:36:14  网络检测正常                                  │  │
│  │ 22:35:02  自动重连成功，网络已恢复（断网时长 1m2s）      │  │
│  │ 22:35:00  检测到断网，开始自动重连…                      │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ▸ 设置（账号 / 密码 / 认证地址 / 静默定时）      ← 固定在底部 │
└──────────────────────────────────────────────────────────────┘
```

设计要点：

1. **状态区字号最大**（21pt）。用户第一眼只想知道"现在到底通不通"。
2. **日志是人话**。底层 `[START]/[AUTH]/[RECOVER]/[DOWN]` 经 `humanize()` 翻译成
   「检测到断网，开始自动重连…」「自动重连成功，网络已恢复（断网时长 1m2s）」；
   `[STATUS]` 这类给机器看的状态行默认不显示，点「详细日志」才看原始记录。
3. **设置区默认折叠、固定在窗口底部、自带滚动条**。日常没人点；字段变多时不会把
   窗口撑出屏幕。

### 1.2 状态机

```
        ┌──────────┐  点「开始守护」   ┌──────────┐  首次探测  ┌──────────┐
        │  待命中   │ ───────────────→ │ 正在检查  │ ─────────→ │  守护中   │
        │  （灰）   │                  │  （黄）   │            │  （绿）   │
        └──────────┘                  └──────────┘            └────┬─────┘
              ↑                                                    │
              │ 点「停止守护」                         探测到断网   │
              │                                                    ↓
              │              ┌──────────┐  成功   ┌──────────┐
              └──────────────│  守护中   │←────────│ 正在重连  │
                             └──────────┘         │  （黄）   │
                                                └────┬─────┘
                                                     │ 失败（后台继续指数退避重试）
                                                     ↓
                                                ┌──────────┐
                                                │ 重连未成功│
                                                │  （红）   │
                                                └──────────┘
```

状态 → 主按钮文案：

| 状态 | 按钮文字 | 颜色 |
|---|---|---|
| 待命中 | `▶  开始守护` | 蓝 |
| 正在检查 / 守护中 | `■  停止守护` | 橙 |
| 正在重连 / 重连未成功 | `■  停止守护`（状态用圆点和副标题表达） | 橙 |

### 1.3 托盘

- 图标随状态更新；提示气泡：`守护中 · 22:36:14`
- 右键菜单：

  ```
  ┌──────────────────────────────┐
  │ 状态: 守护中 · 22:36:14       │  （灰色不可点）
  ├──────────────────────────────┤
  │ 隐藏到托盘                    │
  ├──────────────────────────────┤
  │ 退出                          │  ← 唯一真正结束程序的入口
  └──────────────────────────────┘
  ```

- 点 ✕ → 窗口 `withdraw()`，托盘图标保留，守护继续
- 托盘「退出」→ 停探测线程 → 删图标 → 进程结束
- **托盘创建失败时 ✕ 直接退出**，避免留下一个看不见又停不掉的进程

### 1.4 新增配置项

```jsonc
{
  "close_to_tray": true,        // 场景 A：✕ 缩到托盘(true) 还是直接退出(false)
  "silent_start_time": "",      // 场景 B：静默守护开始时刻 "HH:MM"；留空 = 不启用
  "silent_run_minutes": 30      // 场景 B：守护多久后自动退出
}
```

全部并入 `DEFAULT_CONFIG`，老配置文件不受影响（缺失键自动取默认值）。

**场景 B 的执行语义：**

1. 计划任务在 `silent_start_time` 拉起进程
2. 若启动时刻还没到（手动提前跑），静默待命到点；若已过，立即开始探测
3. 持续探测 → 断网即刻自动重连（复用 A 的同一套退避逻辑）
4. 满 `silent_run_minutes` → 写 `Silent window ended, exiting` → 进程自退

> 手动启动时**绝不为了等窗口而空等一整天**：`plan_silent_window(allow_tomorrow=False)`
> 会立即开跑。这个分歧由 `--now` 显式选择，计划任务不加该参数，行为可预测。

## 2. 技术方案

### 2.1 技术选型与理由

| 选项 | 判定 |
|---|---|
| **tkinter（标准库）** | ✅ 采用。保住「零依赖」原则，exe 仅 11MB，PyInstaller 打包最稳 |
| PyQt5（本机已有 5.15） | ❌ 界面更现代、自带 `QSystemTrayIcon`，但 exe 涨到 40–60MB 且引入依赖 |
| 本地 Web UI（Flask/FastAPI） | ❌ 界面最自由，但多一个进程和端口，Session 0 场景易出问题 |

托盘不引入 `pystray`：项目里 `TrayApp` 已用 ctypes 直调 `Shell_NotifyIconW` 实现完整托盘，`GUITray` 直接继承并只替换右键菜单。

### 2.2 线程模型（最需要小心的一块）

```
主线程        Win32 托盘消息循环（core.TrayApp 的隐藏窗口 + GetMessageW）
窗口线程      tkinter mainloop，root.after(120ms) 轮询 queue.Queue
探测线程      core.run_detection_loop(stop_event, status_callback)
认证线程      点「立即认证一次」时的一次性 core.do_auth
```

**唯一铁律：任何非窗口线程都只能往 `queue` 里放数据，绝不直接调 tk 方法。**
tkinter 跨线程调用会导致随机崩溃与卡死，这是本方案最大的 bug 来源。
参考实现：`QueueSink`（日志）、`StatusSink`（状态行）、`GuiApp._queue_exit`（退出）。
所有控件更新都发生在窗口线程的 `GuiApp._tick` 里。

### 2.3 文件与产物

```
auto_login.py      ← 引擎：CLI + 检测 + 认证（对外契约不变，仅加 hook）
gui_app.py         ← 界面层：窗口 + 托盘 + 两种启动方式，import auto_login as core
setup_task.ps1     ← 新增 -Silent / -SilentAt / -RunMinutes
test_auto_login.py ← 补 14 项测试（纯逻辑，不建 Tk 窗口）
build/CampusNet.spec   ← --windowed 打包配方
assets/campusnet.ico   ← 程序图标
```

**两个产物并存：**

| 产物 | 子系统 | 用途 |
|---|---|---|
| `dist\CampusNet.exe` | GUI（`console=False`） | 双击使用（场景 A）、静默守护（场景 B） |
| `python auto_login.py` / `auto_login.exe` | 控制台 | 排障、`--auth` 校验、CI |

### 2.4 打包

```powershell
pyinstaller --clean --noconfirm build/CampusNet.spec
# → dist\CampusNet.exe，Subsystem = 2 (GUI)，无控制台可闪
```

**为什么必须 `--windowed`：** 场景 B 要求"完全无提示"。旧的 `--console` 打包被计划任务
拉起时，Windows 一定会先创建一个控制台窗口，代码只能事后 `ShowWindow(0)` 藏起来——
那一瞬间是看得见的。只有 GUI 子系统的 exe 才能做到从出生就没有窗口。

## 3. 实施阶段（均已完成）

### 阶段 1 — 核心层解耦

1. `set_log_sink(fn)` / `get_log_sink()`：`log()` 在 print 与写文件之外调用 sink，
   异常被吞掉。**无需修改几十处 `log(...)` 调用点**，现有 `patch.object(app, "log")` 测试继续有效。
2. `run_detection_loop(..., duration_override=None)`：默认行为完全不变。
3. `save_config(config, path)`：写 `.tmp` + fsync + `os.replace()`，原子落盘。
4. `_stdin_available()` / `notify_setup_required()`：`--windowed` 下 `sys.stdin` 是 `None`，
   `input()` 必崩，所有非交互路径改为记日志 + 弹 `messagebox`。
5. `TrayApp` 新增 `status_text` / `on_error` / `on_done` 三个可选参数，供 GUI 复用。

### 阶段 2 — `gui_app.py`

`GuiApp`（窗口+托盘）、`GUITray`（托盘菜单）、`ScrollableFrame`（设置区滚动）、
`humanize()`（日志翻译）、`QueueSink`/`StatusSink`（跨线程入队）。

### 阶段 3 — 打包与部署

`build/CampusNet.spec` 出无控制台 exe；`setup_task.ps1 -Silent` 注册
`CampusNetAutoLogin_Silent` 每日任务，直接运行 `CampusNet.exe --silent --run-minutes N`，
`ExecutionTimeLimit` 随之改为 `N+10` 分钟。

### 阶段 4 — 文档与测试

README 增「两种典型用法」、CLAUDE.md 增 GUI 层与线程模型、配置示例补新字段、
测试从 15 项加到 29 项。

## 4. 风险与取舍（实测结论）

| 风险 | 处置 |
|---|---|
| `--windowed` 下 `stdout` 是 `None` | 现有 `try/except` 已护住；`INTERACTIVE` 为 False；新代码无裸 `print` |
| `--windowed` 下 `input()` 必崩 | 已由 `_stdin_available()` 守卫 + `messagebox` 替代 |
| tkinter 跨线程 | 只走 queue；已写进 CLAUDE.md 的铁律 |
| 杀软误报 | 已加图标；仍未签名，发布页需说明 |
| Session 0（`-Boot`） | `--silent` 完全不构造 `tkinter.Tk()`，不碰任何 UI API |
| 窗口/托盘拼接复杂 | 主线程跑 Win32 消息循环、tk 窗口放子线程，比反过来稳 |
| 双端写配置 | 统一走 `save_config()` 原子写 |
| PowerShell 改 UTF-8 源文件 | 踩过一次：`Get-Content -replace | Set-Content` 按 GBK 读写，会把中文串写坏。已记入 CLAUDE.md |

**回滚成本**：核心业务逻辑未改，`auto_login.py` 与旧 `dist\auto_login.exe` 原样可用，
GUI 是纯增量的一层皮。换 PyQt5 / Web UI 只需重写 `gui_app.py`。
